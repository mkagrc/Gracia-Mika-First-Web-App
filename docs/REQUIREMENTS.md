# UserHub Requirements

| Feature name | Description | Expected behavior | API endpoint | Implementation status |
| --- | --- | --- | --- | --- |
| Registration | Create a USER account with full name, email, and password. | Valid input returns 201; duplicate email returns 409; invalid fields return 400. | `POST /api/auth/register` | Implemented |
| Login | Verify email/password and create a session. | Valid credentials return a UUID bearer token and password-free user data; wrong credentials return 401. Profile picture is loaded from the dashboard, not the login payload. | `POST /api/auth/login` | Implemented |
| Password hashing | Store SHA-256 password digests, never plaintext. | Hash before persistence; password and hash never appear in response DTOs. | Registration/login | Implemented (classroom requirement, not production-grade) |
| Token authentication | Authenticate with an in-memory token-to-user-ID map. | Protected requests require `Authorization: Bearer <token>`; invalid or missing token returns 401. | Protected endpoints | Implemented |
| Role-based authorization | Restrict user-list access to ADMIN. | USER remains unable to view other users; backend returns 403 and frontend route is ADMIN-only. | `GET /api/dashboard/users` | Implemented |
| USER dashboard | Show a signed-in USER's concise account summary. | Shows “Welcome, {fullName}!”, avatar/fallback and role badge; Account Summary contains only email, member-since date/time and total users. Address and phone are shown on `/profile`; Profile and Logout are in the navbar; no dashboard edit button. | `GET /api/dashboard` | Implemented |
| ADMIN dashboard | Show administrator-specific concise overview. | Shows “Welcome Admin, {fullName}!”, ADMIN badge and avatar/fallback; Account Summary contains only email, member-since date/time and total users; retains View all users. Address and phone are shown on `/profile`; Profile and Logout are in the navbar; no dashboard edit button. | `GET /api/dashboard` | Implemented |
| Profile view | Display the signed-in user's detailed profile without editable fields. | `/profile` loads the current dashboard data and shows avatar/initials, full name, email, address, phone or “Not set”, role badge, and member-since date/time; Edit Profile opens `/profile/edit`. | `GET /api/dashboard` | Implemented |
| Address | Save optional address in the user profile. | Address is limited to 255 characters; blank values are stored as unset and shown as “Not set”. | `PUT /api/users/me` | Implemented |
| Phone | Save optional phone number. | At most 20 characters and only digits, plus, hyphen, and spaces; invalid values return 400 JSON error. | `PUT /api/users/me` | Implemented |
| Profile picture | Upload JPEG or PNG as a Base64 data URL in the user profile. | Client and server limit file size to 1 MB; server validates MIME data URL, Base64 and image signature; picture is returned by dashboard/profile response but omitted from login and admin list. | `PUT /api/users/me`; picture returned by `GET /api/dashboard` | Implemented |
| Member-since timestamp | Store account creation date and time. | `createdAt`/`memberSince` use LocalDateTime; frontend displays via `toLocaleString()`. | `GET /api/dashboard`; `GET /api/dashboard/users` | Implemented |
| Profile update | Update full name and optional address, phone and profile picture for the authenticated user. | Edit at `/profile/edit` from the Edit Profile button on `/profile`; email is read-only; Cancel returns to `/profile`; successful save returns to `/profile`, re-fetches the dashboard data, updates only name/role in localStorage and stores no picture there. | `PUT /api/users/me` | Implemented |
| Validation errors | Reject invalid profile phone and picture input. | Invalid phone, unsupported image type/data and images above 1 MB return HTTP 400 with `{ "error": "..." }`; duplicate registration remains 409. | `PUT /api/users/me`; `POST /api/auth/register` | Implemented |
| Protected dashboard | Return the authenticated user's summary and total user count. | Any logged-in role can retrieve own profile summary; unauthenticated calls return 401. | `GET /api/dashboard` | Implemented |
| ADMIN users page | Display all users to administrators. | ADMIN sees ID, name, email, role and member-since timestamp; pictures/passwords are omitted; USER receives 403. | `GET /api/dashboard/users` | Implemented |
| Exception handling | Convert expected failures to readable JSON. | Authentication 401, forbidden 403, validation/bad profile input 400, duplicate email 409, all with `{ "error": "..." }`. | API-wide | Implemented |
| Seed ADMIN | Create the documented ADMIN if missing. | `CommandLineRunner` seeds `admin@userhub.com` with classroom password `admin12345` and hashes it. | Application startup | Implemented |
| Server-side logout | Revoke current bearer token. | The protected-page navbar Logout button calls the endpoint; logout removes the token from the session map, then the frontend clears localStorage and navigates to login in `finally`. | `POST /api/auth/logout` | Implemented |
| Protected routes | Keep dashboard, profile view, profile edit, and admin page behind client guards. | Missing token redirects to login; `/profile` and `/profile/edit` require login; non-admin access to `/admin/users` redirects to dashboard; backend independently enforces ADMIN permission. | Frontend routes | Implemented |
| Axios API client | Share API base URL and attach bearer credentials. | Requests use `http://localhost:8080/api` and read the token from localStorage. | Frontend API client | Implemented |
